## 3. 静态 IP + 主机名 + hosts

### 3.1 配置静态 IP

> **每台都要执行**，IP 地址各不同！

```bash
sudo vim /etc/sysconfig/network-scripts/ifcfg-ens33
```

> 网卡名可能是 `ens33`、`eth0` 等，用 `ip addr` 查看你的实际网卡名。

修改以下内容：

```ini
# 将 dhcp 改为 static
BOOTPROTO="static"

# 末尾添加（hadoop100 为例，101/102 对应改 IP）
IPADDR=192.168.100.130
GATEWAY=192.168.100.2
DNS1=192.168.100.2
DNS2=8.8.8.8
```

三台机器各填自己的 IP：

| 机器 | IPADDR |
|------|--------|
| hadoop100 | 192.168.100.130 |
| hadoop101 | 192.168.100.131 |
| hadoop102 | 192.168.100.132 |

保存后重启网络：

```bash
sudo systemctl restart network
```

> **报错**：`Restarting network (via systemctl): Job for network.service failed`
> **原因**：ifcfg-ens33 配置有误（MAC 地址不匹配、格式错误）
> **解决**：检查文件内容，确认网卡名是否与 `ip addr` 输出的网卡名一致。如果用的是 VMware 克隆的虚拟机，需要额外修改 `HWADDR` 或 `UUID`。

### 3.2 修改主机名

> **每台都要执行**

```bash
# hadoop100 上执行
sudo hostnamectl set-hostname hadoop100

# hadoop101 上执行
sudo hostnamectl set-hostname hadoop101

# hadoop102 上执行
sudo hostnamectl set-hostname hadoop102
```

改完后执行 `bash` 或重新登录，终端才会显示新主机名。

### 3.3 配置 hosts 映射

> **每台都要执行**

```bash
sudo vim /etc/hosts
```

添加以下内容到文件末尾：

```
192.168.100.130  hadoop100
192.168.100.131  hadoop101
192.168.100.132  hadoop102
```

> **重要**：如果文件中有 `127.0.0.1 hadoopXXX` 这样的行，注释掉或删除。否则后续 Hadoop/Kafka 等组件绑定 IP 时会出问题（典型的 `UnknownHostException` 往往由此引起）。

### 3.4 验证网络

```bash
# 在 hadoop100 上执行
ping -c 2 hadoop101
ping -c 2 hadoop102
```

**预期**：三台两两互通，延迟 < 1ms。

## 4. 关闭防火墙 + SELinux

> **每台都要执行**。大数据集群内部通信频繁，防火墙和 SELinux 是 90% 组件通信故障的罪魁祸首。

```bash

sudo systemctl disable firewalld.service

sudo sed -i 's/^SELINUX=.*/SELINUX=disabled/' /etc/selinux/config
```

验证：

```bash

sudo systemctl status firewalld

# SELinux 应为 Disabled

```

## 6. 集群分发脚本 xsync

> 只须在 **hadoop100** 上创建，注册到 PATH 后全局可用。

### 6.1 创建脚本

```bash
vim /home/hadoop/bin/xsync
```

写入以下内容：

```bash
#!/bin/bash

# ====== 集群主机列表（统一维护，改这里即可）======
HOSTS="hadoop100 hadoop101 hadoop102"

# 判断参数个数
if [ $# -lt 1 ]; then
  echo "Usage: xsync <file1/dir1> [file2/dir2] ..."
  exit 1
fi

# 遍历集群所有机器
for host in $HOSTS; do
  echo "==================== $host ===================="

  for file in "$@"; do
    # 判断文件是否存在
    if [ -e "$file" ]; then
      pdir=$(cd -P "$(dirname "$file")" && pwd)
      fname=$(basename "$file")
      
      # 远程创建目录（sudo 提权）
      ssh $host "sudo mkdir -p $pdir"
      if [ $? -eq 0 ]; then
        # rsync 远程端同样 sudo 提权
        rsync -av --rsync-path="sudo rsync" "$pdir/$fname" "$host:$pdir"
      else
        echo "ERROR: Failed to create directory on $host"
      fi
    else
      echo "ERROR: $file does not exist!"
    fi
  done
done
```

> 与原版差异：主机列表独立为 `HOSTS` 变量，日后增删节点只改一处；增加了错误提示；`rsync` 不依赖 `sudo`。

### 6.2 赋予权限并分发

```bash
chmod 777 /home/hadoop/bin/xsync

# 首次分发：用 scp 手动推到另外两台
scp -r /home/hadoop/bin hadoop101:/home/hadoop/
scp -r /home/hadoop/bin hadoop102:/home/hadoop/

# 验证：把脚本自己复刻一遍
xsync /home/hadoop/bin/xsync
```

> **报错：`rsync: command not found`** → `sudo yum install -y rsync`（第2步已装，一般不会遇到）
>
> **报错：`Permission denied`** → SSH 免密还没配，下一节解决。scp 和 rsync 暂时手动输密码。

## 8. SSH 免密登录配置

> **免密的正确姿势**：所有节点互信（每台都生成密钥 → 每台都发到所有节点）。为什么要全互信？因为后续很可能在任意一台节点上执行脚本访问其他节点。

> 这里root账户和hadoop账户我都做了免密

### 8.1 在 hadoop100 上配置

```bash
# 1. 生成密钥对（三个回车，不设密码）
ssh-keygen -t rsa

# 2. 公钥拷贝到三台（包括自己）
ssh-copy-id hadoop100
ssh-copy-id hadoop101
ssh-copy-id hadoop102
```

执行 `ssh-copy-id` 时输入目标机器的 hadoop 用户密码。

### 8.2 在 hadoop101 上配置

```bash
ssh-keygen -t rsa
ssh-copy-id hadoop100
ssh-copy-id hadoop101
ssh-copy-id hadoop102
```

### 8.3 在 hadoop102 上配置

```bash
ssh-keygen -t rsa
ssh-copy-id hadoop100
ssh-copy-id hadoop101
ssh-copy-id hadoop102
```

### 8.4 验证

```bash
# 在 hadoop100 上执行
ssh hadoop101    # 免密码直接登录即成功
exit

ssh hadoop102    # 同理
exit
```

> **报错：`Permission denied (publickey)`**
>
> 原因：目标机器的 `~/.ssh/authorized_keys` 权限不正确
>
> 解决：**在目标机器上**执行：
> ```bash
> chmod 700 ~/.ssh
> chmod 600 ~/.ssh/authorized_keys
> ```
>
> **报错：`ssh-copy-id: command not found`**
>
> 原因：CentOS 最小化安装缺少该命令
>
> 解决：`sudo yum install -y openssh-clients`

## 9. 集群时钟同步

> **每台都要执行**。Hadoop/Kafka/HBase 等大量组件依赖时间戳，集群时间不一致会导致数据错乱、任务失败。

```bash
# 安装 ntpdate
sudo yum install -y ntpdate

# 首次同步（阿里云 NTP 服务器）
sudo ntpdate ntp.aliyun.com

# 设置定时任务：每天凌晨 2 点自动同步
sudo crontab -e
```

在 crontab 中加入以下行（第一行），保存退出：

```
0 2 * * * /usr/sbin/ntpdate ntp.aliyun.com
```

> 这只是教学环境方案。生产环境建议部署本地 NTP 服务器（如 hadoop100 部署 ntpd，其余节点指向它），避免所有节点同时请求外部服务器。
>
> **报错：`ntpdate: command not found`** → `sudo yum install -y ntpdate`
>
> **报错：`crontab: command not found`** → `sudo yum install -y crontabs`

## 10. JDK 安装

### 10.1 卸载已有 JDK

```bash
# SSH免密已配好，用 xcall 三台批量操作
xcall "sudo rpm -qa | grep -i java | xargs -r sudo rpm -e --nodeps 2>/dev/null"
```

> 参数含义：
> - `rpm -qa` — 查询所有已安装软件包
> - `grep -i java` — 不区分大小写过滤
> - `xargs -r` — 逐条卸载（`-r` 表示无匹配项时不执行，避免报错）
> - `rpm -e --nodeps` — 强制卸载，忽略依赖

### 10.2 下载并安装 JDK

在 **hadoop100** 上操作：

#### Oracle JDK（课程文档推荐，稳定）

```bash
# 将 jdk-8u212-linux-x64.tar.gz 上传到 /opt/software/
# 用 XShell 的 rz、WinSCP、scp 等工具

# 解压
tar -zxvf /opt/software/jdk-8u212-linux-x64.tar.gz -C /opt/module/

# 重命名
mv /opt/module/jdk1.8.0_212 /opt/module/jdk-1.8.0
```

### 10.3 配置环境变量

```bash
sudo vim /etc/profile.d/my_env.sh
```

写入：

```bash
# JAVA_HOME
export JAVA_HOME=/opt/module/jdk-1.8.0
export PATH=$JAVA_HOME/bin:$PATH
export CLASSPATH=.:$JAVA_HOME/lib/dt.jar:$JAVA_HOME/lib/tools.jar
```

> **为什么放在 `/etc/profile.d/my_env.sh`？** login shell 和 non-login shell 都会加载该目录下所有 `.sh`，全局可用。后续所有组件（Hadoop/Hive/Kafka 等）的环境变量都追加到这个文件。

### 10.4 验证

```bash
source /etc/profile
java -version
```

预期输出类似：

```
openjdk version "1.8.0_492"
OpenJDK Runtime Environment (build 1.8.0_492-b09)
OpenJDK 64-Bit Server VM (build 25.492-b09, mixed mode)
```

### 10.5 分发 JDK + 环境变量

```bash
# 分发 jdk
xsync /opt/module/jdk-1.8.0

# 分发环境变量
xsync /etc/profile.d/my_env.sh

# 三台机器刷新环境变量
xcall "source /etc/profile"
```

### 10.6 确认三台 JDK 都可用

```bash
xcall java -version
```

三台都应该正常输出版本信息。

### 4.1 核心配置：core-site.xml

```bash
vim /opt/module/hadoop/etc/hadoop/core-site.xml
```

内容如下（`<configuration>` 标签内）：

```xml
<configuration>

    <value>hdfs://hadoop100:8020</value>

    <name>hadoop.http.staticuser.user</name>
    <value>hadoop</value>
</property>

<!-- 配置 hadoop(superUser) 允许通过代理访问的主机节点 -->
<property>
    <name>hadoop.proxyuser.hadoop.hosts</name>
    <value>*</value>
</property>

<!-- 配置 hadoop(superUser) 允许通过代理用户所属组 -->
<property>
    <name>hadoop.proxyuser.hadoop.groups</name>
    <value>*</value>
</property>

<!-- 配置 hadoop(superUser) 允许通过代理的用户 -->
<property>
    <name>hadoop.proxyuser.hadoop.users</name>
    <value>*</value>
</property>
</configuration>
```

### 4.2 HDFS 配置：hdfs-site.xml

```bash
vim /opt/module/hadoop/etc/hadoop/hdfs-site.xml
```

```xml
<configuration>
<!-- NameNode web 界面地址 -->
```

> ```xml

> </property>
> ```

### 4.3 YARN 配置：yarn-site.xml

```bash
vim /opt/module/hadoop/etc/hadoop/yarn-site.xml
```

```xml
<configuration>
<!-- 指定 MR 走 shuffle -->
<property>
    <name>yarn.nodemanager.aux-services</name>
    <value>mapreduce_shuffle</value>
</property>

<!-- 指定 ResourceManager 地址（部署在 hadoop101） -->
<property>
    <name>yarn.resourcemanager.hostname</name>
    <value>hadoop101</value>
</property>

<!-- 环境变量继承（避免 classpath 问题） -->
<property>
    <name>yarn.nodemanager.env-whitelist</name>
    <value>JAVA_HOME,HADOOP_COMMON_HOME,HADOOP_HDFS_HOME,HADOOP_CONF_DIR,CLASSPATH_PREPEND_DISTCACHE,HADOOP_YARN_HOME,HADOOP_MAPRED_HOME</value>
</property>

<!-- ====== 4GB 节点内存调优（必须配置） ====== -->

<!-- YARN 单个容器允许分配的最小/最大内存 -->
<property>
    <name>yarn.scheduler.minimum-allocation-mb</name>
    <value>512</value>
</property>
<property>
    <name>yarn.scheduler.maximum-allocation-mb</name>
    <value>4096</value>
</property>

<!-- YARN 每节点可用物理内存（4GB 总内存，留 ~2GB 给 OS/ZK/Kafka 等） -->
<property>
    <name>yarn.nodemanager.resource.memory-mb</name>
    <value>4096</value>
</property>

<!-- 关闭物理内存检查（4GB 节点必须关，否则容器会被 YARN 误杀） -->
<property>
    <name>yarn.nodemanager.pmem-check-enabled</name>
    <value>false</value>
</property>

<!-- 关闭虚拟内存检查 -->
<property>
    <name>yarn.nodemanager.vmem-check-enabled</name>
    <value>false</value>
</property>

<!-- 开启日志聚集 -->
<property>
    <name>yarn.log-aggregation-enable</name>
    <value>true</value>
</property>

<!-- 日志聚集服务器地址 -->
<property>
    <name>yarn.log.server.url</name>
    <value>http://hadoop100:19888/jobhistory/logs</value>
</property>

<!-- 日志保留 7 天 -->
<property>
    <name>yarn.log-aggregation.retain-seconds</name>
    <value>604800</value>
</property>
</configuration>
```

> **为什么必须关 pmem-check**：YARN 默认会监控容器实际物理内存使用量，如果超过申请值就杀容器。但在 4GB 低内存环境下，JVM 堆外内存和各种 overhead 很容易让实际使用量超过申请值。关闭后 YARN 不再检查，避免无辜杀容器。

## 6. Kafka 数据有序

Kafka 只保证**分区内**有序、跨分区不保证。本项目要求同一授信申请（`credit_facility_id`）的流转记录能被正确关联，因此做如下约束：

- ODS 各 topic 显式创建为 **3 分区 2 副本**（建 topic 时指定分区数，见《02-数仓建模开发.md》第 2.4 节）；
- DWD 作业并行度设为 1，单并行度消费所有分区，配合「谁先到谁等」的状态等待机制处理跨表乱序。

`server.properties` 中的 `num.partitions` 是**自动创建 topic** 的默认分区数，保持与显式建 topic 一致设为 3：

```bash
[hadoop@hadoop100 ~]$ cd /opt/module/kafka/
[hadoop@hadoop100 kafka]$ vim config/server.properties
```

```properties
# 自动创建 topic 的默认分区数（显式建 topic 时仍以创建命令指定的为准）
num.partitions=3
```

三台服务器的配置文件都要修改，修改完毕重启 Kafka，不可直接分发配置文件，因为每个节点的 broker.id 必须唯一。分发后必须修改 broker.id 才能重启 Kafka，否则重启失败。

> **重要**：停止 Kafka 集群时，一定要等 Kafka 所有节点进程全部停止后再停止 Zookeeper 集群。因为 ZK 中记录了 Kafka 集群信息，ZK 先停会导致 Kafka 无法正常关闭，只能手动 kill 进程。

| hadoop100 | JobManager + TaskManager |
| hadoop101 | TaskManager |
| hadoop102 | TaskManager |

### 1.2 下载并解压安装包

（1）下载安装包 `flink-1.17.1-bin-scala_2.12.tgz`，将该 jar 包上传到 hadoop100 节点服务器的 `/opt/software` 路径上。

（2）在 `/opt/software` 路径上解压 `flink-1.17.1-bin-scala_2.12.tgz` 到 `/opt/module` 路径上。

```bash
[hadoop@hadoop100 software]$ tar -zxvf flink-1.17.1-bin-scala_2.12.tgz -C /opt/module/
```

### 1.3 修改集群配置

（1）进入 conf 路径，修改 `flink-conf.yaml` 文件，指定 hadoop100 节点服务器为 JobManager。

```bash
[hadoop@hadoop100 conf]$ vim flink-conf.yaml
```

修改如下内容：

```yaml
# JobManager 节点地址
jobmanager.rpc.address: hadoop100
jobmanager.bind-host: 0.0.0.0
rest.address: hadoop100
rest.bind-address: 0.0.0.0
# TaskManager 节点地址，需要配置为当前机器名
taskmanager.bind-host: 0.0.0.0
taskmanager.host: hadoop100
```

（2）修改 `workers` 文件，指定 hadoop100、hadoop101 和 hadoop102 为 TaskManager。

```bash
[hadoop@hadoop100 conf]$ vim workers
```

修改如下内容：

```
hadoop100
hadoop101
hadoop102
```

（3）修改 `masters` 文件。

```bash
[hadoop@hadoop100 conf]$ vim masters
```

修改如下内容：

```
hadoop100:8081
```

（4）另外，在 `flink-conf.yaml` 文件中还可以对集群中的 JobManager 和 TaskManager 组件进行优化配置，主要配置项如下：

- `jobmanager.memory.process.size`：对 JobManager 进程可使用到的全部内存进行配置，包括 JVM 元空间和其他开销，默认为 1600M，可以根据集群规模进行适当调整。
- `taskmanager.memory.process.size`：对 TaskManager 进程可使用到的全部内存进行配置，包括 JVM 元空间和其他开销，默认为 1728M，可以根据集群规模进行适当调整。
- `taskmanager.numberOfTaskSlots`：对每个 TaskManager 能够分配的 Slot 数量进行配置，默认为 1，可根据 TaskManager 所在的机器能够提供给 Flink 的 CPU 数量决定。所谓 Slot 就是 TaskManager 中具体运行一个任务所分配的计算资源。
- `parallelism.default`：Flink 任务执行的并行度，默认为 1。优先级低于代码中进行的并行度配置和任务提交时使用参数指定的并行度数量。

### 1.4 分发安装目录

（1）配置修改完毕后，将 Flink 安装目录分发给另外两个节点服务器。

```bash
[hadoop@hadoop100 module]$ xsync flink-1.17.1/
```

（2）修改 hadoop101 的 `taskmanager.host`。

```bash
[hadoop@hadoop101 conf]$ vim flink-conf.yaml
```

修改如下内容：

```yaml
# TaskManager 节点地址，需要配置为当前机器名
taskmanager.host: hadoop101
```

（3）修改 hadoop102 的 `taskmanager.host`。

```bash
[hadoop@hadoop102 conf]$ vim flink-conf.yaml
```

修改如下内容：

```yaml
# TaskManager 节点地址，需要配置为当前机器名
taskmanager.host: hadoop102
```

### 1.5 启动集群

（1）在 hadoop100 节点服务器上执行 `start-cluster.sh` 启动 Flink 集群：

```bash
[hadoop@hadoop100 flink-1.17.1]$ bin/start-cluster.sh
```

（2）查看进程情况：

```bash
[hadoop@hadoop100 flink-1.17.1]$ jpsall
```

预期输出：

```
=============== hadoop100 ===============
4453 StandaloneSessionClusterEntrypoint
4458 TaskManagerRunner
4533 Jps
=============== hadoop101 ===============
2872 TaskManagerRunner
2941 Jps
=============== hadoop102 ===============
2948 Jps
2876 TaskManagerRunner
```

> hadoop100 同时运行 `StandaloneSessionClusterEntrypoint`（JobManager）和 `TaskManagerRunner`（TaskManager），hadoop101、hadoop102 仅运行 `TaskManagerRunner`。

### 1.6 访问 Web UI

启动成功后，同样可以访问 http://hadoop100:8081 对 Flink 集群和任务进行监控管理。

> 这里可以明显看到，当前集群的 TaskManager 数量为 3；由于默认每个 TaskManager 的 Slot 数量为 1，所以总 Slot 数和可用 Slot 数都为 3。

# 七、Doris 2.1.0 安装

## 1. 操作系统安装要求

### 1.1 设置系统最大打开文件句柄数

```bash
sudo vim /etc/security/limits.conf
```

```text
* soft nofile 65536
* hard nofile 65536
```

> 重启永久生效，也可以用 `ulimit -n 65535` 临时生效。

### 1.2 设置进程可以拥有的内存映射区域（mmap）数量限制（BE 节点需要）

```bash
sudo vim /etc/sysctl.conf
```

```text
vm.max_map_count=2000000
```

> 重启永久生效，也可以用 `sudo sysctl -w vm.max_map_count=2000000` 临时生效。

### 1.3 时钟同步

Doris 的元数据要求时间精度小于 5000ms，所以集群所有机器要进行时钟同步，避免因为时钟问题引发的元数据不一致导致服务出现异常。

- 如果服务器在公网环境（能连接外网），可以不采用集群时间同步，因为服务器会定期和公网时间进行校准
- 如果服务器在内网环境，必须配置集群时间同步，否则时间久了会产生时间偏差，导致集群执行任务时间不同步

> 本项目为外网环境，并且之前已经配置过集群时间同步（见本文档「一、服务器基础环境准备」第 9 节）。

### 1.4 关闭交换分区（swap）

Linux 交换分区会给 Doris 带来很严重的性能问题，需要在安装之前禁用交换分区。

```bash
# 查看 swap 状态，swap 这一行不全为 0 表示 swap 是开启的
free -m

# 永久关闭
sudo vim /etc/fstab
# 注释掉带有 swap 的这一行，重启系统
```

## 3. 部署 FE 节点（hadoop100）

### 3.1 上传并解压 FE

```bash
tar -zxvf apache-doris-2.1.0-bin-x64.tar.gz -C /opt/module/

cd /opt/module/
mv apache-doris-2.1.0-bin-x64 doris2.1
```

### 3.2 创建 FE 元数据存储目录

```bash
mkdir -p /opt/module/doris2.1/fe/doris-meta
```

### 3.3 修改 FE 配置文件

```bash
vim /opt/module/doris2.1/fe/conf/fe.conf
```

```text
# 配置文件中指定元数据路径
meta_dir = /opt/module/doris2.1/fe/doris-meta
# 修改绑定 ip（每台机器修改成自己的 ip）
priority_networks = 192.168.100.130/24
enable_fqdn_mode = true
```

> 注意：
> - 生产环境强烈建议单独指定元数据目录，不要放在 Doris 安装目录下，最好是单独的磁盘（如果有 SSD 最好）
> - 如果机器有多个 ip，比如内网外网、虚拟机 docker 等，需要进行 ip 绑定，才能正确识别
> - `JAVA_OPTS` 默认 java 最大堆内存为 4GB，建议生产环境调整至 8G 以上

### 3.4 启动 hadoop100 的 FE

```bash
/opt/module/doris2.1/fe/bin/start_fe.sh --daemon
```

## 4. 配置并启动 BE 节点（hadoop101、hadoop102）

### 4.1 在 hadoop101 上创建 BE 数据存放目录

```bash
mkdir /opt/module/doris2.1/be/storage
```

### 4.2 修改 hadoop101 的 BE 配置文件

```bash
vim /opt/module/doris2.1/be/conf/be.conf
```

```text
# 配置文件中指定数据存放路径
storage_root_path = /opt/module/doris2.1/be/storage
# 修改端口，避免与 hadoop 端口冲突
webserver_port = 18040
# 修改绑定 ip（每台机器修改成自己的 ip）
priority_networks = 192.168.100.131/24
```

> 注意：
> - `storage_root_path` 默认在 `be/storage` 下，需要手动创建该目录。多个路径之间使用英文状态的分号 `;` 分隔（最后一个目录后不要加）
> - 可以通过路径区别存储目录的介质，HDD 或 SSD。可以添加容量限制在每个路径的末尾，通过英文状态逗号 `,` 隔开，如：
>   `storage_root_path=/home/disk1/doris.HDD,50;/home/disk2/doris.SSD,10;/home/disk2/doris`
> - 如果机器有多个 IP，比如内网外网、虚拟机 docker 等，需要进行 IP 绑定，才能正确识别
> - 如果 BE 部署在 hadoop 集群中，注意调整 `be.conf` 中的 `webserver_port = 18040`，以免造成端口冲突
> - 配置 `JAVA_HOME` 环境变量：由于从 1.2 版本开始支持 Java UDF 函数，BE 依赖于 Java 环境。所以要预先配置 `JAVA_HOME` 环境变量，也可以在 `start_be.sh` 启动脚本第一行添加 `export JAVA_HOME=your_java_home_path` 来添加环境变量

### 4.3 分发 BE 到 hadoop102

```bash
# 在 hadoop101 上执行，将 doris2.1 目录分发到 hadoop102
scp -r /opt/module/doris2.1 hadoop102:/opt/module/
```

### 4.4 修改 hadoop102 的绑定 IP

```bash
# 在 hadoop102 上执行
vim /opt/module/doris2.1/be/conf/be.conf

# 修改绑定 ip
priority_networks = 192.168.100.132/24
```

### 4.5 安装 MySQL Client（在 hadoop100 上）

BE 节点需要先在 FE 中添加，才可加入集群。可以使用 mysql-client 连接到 FE。

**（1）创建目录**

```bash
mkdir /opt/software/mysql-client/
```

**（2）上传以下三个 rpm 包到 `/opt/software/mysql-client/`**

- `mysql-community-client-5.7.28-1.el7.x86_64.rpm`
- `mysql-community-common-5.7.28-1.el7.x86_64.rpm`
- `mysql-community-libs-5.7.28-1.el7.x86_64.rpm`

**（3）检查当前系统是否安装过 MySQL**

```bash
sudo rpm -qa | grep mariadb

# 如果存在，先卸载
sudo rpm -e --nodeps mariadb mariadb-libs mariadb-server
```

**（4）安装**

```bash
rpm -ivh /opt/software/mysql-client/*
```

### 4.6 使用 MySQL Client 连接 FE 并添加 BE 节点

FE 的查询端口默认 9030。

```bash
mysql -h hadoop100 -P 9030 -uroot
```

> 默认 root 无密码，通过以下命令修改 root 密码：

```sql
SET PASSWORD FOR 'root' = PASSWORD('root');
```

添加 BE（BE 的心跳端口默认 9050）：

```sql
ALTER SYSTEM ADD BACKEND "hadoop101:9050";
ALTER SYSTEM ADD BACKEND "hadoop102:9050";
```

查看 BE 状态：

```sql
SHOW PROC '/backends' \G;
```

### 4.7 启动 BE（每个 BE 节点）

```bash
# 在 hadoop101 上执行
/opt/module/doris2.1/be/bin/start_be.sh --daemon

# 在 hadoop102 上执行
/opt/module/doris2.1/be/bin/start_be.sh --daemon
```

### 4.8 查看 BE 状态

```bash
mysql -h hadoop100 -P 9030 -uroot -p
```

```sql
SHOW PROC '/backends' \G;
```

> `Alive` 为 `true` 表示该 BE 节点存活。
