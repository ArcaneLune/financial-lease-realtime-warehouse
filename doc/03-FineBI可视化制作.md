# 金融租赁数仓 ADS 层 FineBI 可视化制作文档

> 目标：把 Doris `ads` 库的 7 张 ADS 物化视图，通过 FineBI 做成一个「经营分析驾驶舱」大屏/报表。
> 数据源：Doris（MySQL 协议），`hadoop100:9030`，库 `ads`，账号 root/root。
> 前提：FineBI 已安装，能访问 `hadoop100:9030`。

---

## 一、准备工作（一次性）

### 1.1 连接 Doris 数据源

1. 登录 FineBI → **管理系统 → 数据连接 → 新建数据连接** → 选择 **MySQL**。
2. 填写：
   | 参数 | 值 |
   |---|---|
   | 数据库名 | `ads` |
   | 主机 | `hadoop100` |
   | 端口 | `9030` |
   | 用户名 | `root` |
   | 密码 | `root` |
   | 编码 | `UTF-8` |
3. 点「**测试连接**」→ 成功 → 保存。

### 1.2 导入 7 张 ADS 数据集

**公共数据 → 新建数据集 → 选「数据库表」** → 在 ads 连接下勾选以下 7 张表 → 导入 → **刷新每个数据集**：

| 数据集名 | 来源表 | 用途 |
|---|---|---|
| ads_综合统计 | mv_ads_audit_result_summary | 审批通过/取消/拒绝 KPI |
| ads_转化漏斗 | mv_ads_credit_transform | 授信转化漏斗 |
| ads_业务方向 | mv_ads_audit_result_org | 各业务方向 |
| ads_行业 | mv_ads_audit_result_industry | 各行业（3级） |
| ads_部门 | mv_ads_audit_result_dept | 各部门（3级） |
| ads_业务经办 | mv_ads_audit_result_salesman | 各业务经办 |
| ads_信审经办 | mv_ads_audit_result_audit_man | 各信审经办 |

> 提醒：Doris 物化视图是 5 分钟刷新，FineBI 数据集建议也设置定时刷新（或每次打开前手动刷新），保证数据是最新的。

---

## 二、仪表板整体设计

新建一个仪表板「**ADS 经营分析驾驶舱**」，建议布局：

```
┌─────────────────────────────────────────────────┐
│  顶部：4 个 KPI 卡片（通过数/通过金额/取消数/拒绝数） │
├──────────────────┬──────────────────────────────┤
│  中部左：授信转化漏斗图 │  中部右：业务方向饼图         │
├──────────────────┴──────────────────────────────┤
│  下部：行业柱状图 │ 部门排行 │ 经办排行 │ 信审经办排行 │
└─────────────────────────────────────────────────┘
```

## 三、各业务表制作方法（流程顺序）

### 表 1：ads_综合统计（KPI 卡片）

**业务含义**：历史至今 审批通过/取消/拒绝 的项目数、申请金额、批复金额。

**制作流程**：
1. 仪表板添加「**指标卡**」组件 → 数据集选 `ads_综合统计`。
2. 添加过滤条件 `audit_result = approve`。
3. 拖 `project_count` 到指标 → 显示「审批通过项目数」（预期 1328）。
4. 复制卡片，改成 `apply_amount` → 「审批通过申请金额」（667,488,725.35）。
5. 再复制两张，过滤分别改 `cancel` / `reject` → 「取消项目数」「拒绝项目数」。
6. 样式：大数字、配色区分（通过=绿、取消=黄、拒绝=红）。

---

### 表 2：ads_转化漏斗（漏斗图）

**业务含义**：授信漏斗 5 环节项目数（新增授信→授信占用→合同制作→签约→起租），看转化流失。

**制作流程**：
1. 添加「**漏斗图**」组件 → 数据集选 `ads_转化漏斗`。
2. 维度拖 `transform_step`，指标拖 `project_count`。
3. 按项目数排序：`credit_add(1272) → credit_occupy(1035) → contract_produce(940) → lease_sign(884) → lease_execution(702)`。
4. 可开启「漏斗图百分比」，显示各环节相对上一环节的转化率。

---

### 表 3：ads_业务方向（饼图）

**业务含义**：各业务方向审批通过项目数的占比。

**制作流程**：
1. 添加「**饼图**」（或环形图）→ 数据集 `ads_业务方向`。
2. 维度拖 `lease_organization`，指标拖 `project_count`。
3. 加过滤 `audit_result = approve`（看通过分布）。
4. 显示标签：项目数 + 占比。
5. 进阶：加一个「下拉筛选器」绑定 `audit_result`，让用户切换 通过/取消/拒绝 看不同分布。

---

### 表 4：ads_行业（柱状图 + 下钻）

**业务含义**：各行业审批通过金额，支持一级→二级→三级下钻。

**制作流程**：
1. 添加「**柱状图**」→ 数据集 `ads_行业`。
2. 维度拖 `industry1_name`（一级行业），指标拖 `apply_amount`。
3. 加过滤 `audit_result = approve`。
4. **开启下钻**：在维度上把 `industry1_name → industry2_name → industry3_name` 依次加入，开启维度下钻。
5. 效果：点一级行业（如「轻工」）下钻到二级（服装业/纺织业），再下钻到三级（服装销售/服装生产…）。

---

### 表 5：ads_部门（柱状图排行）

**业务含义**：各部门（三级）审批项目数排行。

**制作流程**：
1. 添加「**柱状图**」→ 数据集 `ads_部门`。
2. 维度拖 `department3_name`，指标拖 `project_count`。
3. 加过滤 `audit_result = approve`。
4. 排序取 TOP10，开启 `department1/2/3` 维度下钻。
5. 效果：看哪个三级部门业绩最好，点部门可下钻。

---

### 表 6：ads_业务经办（柱状图 TOP 榜）

**业务含义**：各业务经办审批通过业绩排行。

**制作流程**：
1. 添加「**柱状图**」→ 数据集 `ads_业务经办`。
2. 维度拖 `salesman_name`，指标拖 `project_count`。
3. 加过滤 `audit_result = approve`。
4. 排序取 TOP10（业绩榜），可同时展示 `apply_amount`（金额榜）。
5. 样式：横向柱状图更适合人名排行。

---

### 表 7：ads_信审经办（柱状图）

**业务含义**：各信审经办审批通过业绩。

**制作流程**：
1. 添加「**柱状图**」→ 数据集 `ads_信审经办`。
2. 维度拖 `audit_man_name`，指标拖 `project_count`。
3. 加过滤 `audit_result = approve` **且 audit_man_name 不为空**（排除无信审经办的记录）。
4. 排序取 TOP10，展示各信审经办审批量。

## 四、联动与交互（进阶）

1. **组件联动**：仪表板 → 组件联动 → 让「行业柱状图」作为联动源，其它组件随所选行业联动过滤（看某行业下各部门/经办表现）。
2. **筛选器**：顶部加一个「审批结果筛选器」（audit_result），全局控制通过/取消/拒绝。
3. **实时刷新**：FineBI 数据集设置定时刷新（如 5 分钟），配合 Doris 物化视图 5 分钟刷新，实现近实时大屏。

---

## 五、常见问题排查

| 问题 | 原因/解决 |
|---|---|
| 数据集没数据 | 先 `select * from ads.mv_ads_xxx` 确认 Doris 有数据；刷新 FineBI 数据集 |
| 漏斗图顺序乱 | 按 project_count 降序排列，或用 transform_step 自定义顺序 |
| 下钻不生效 | 确认维度按 1→2→3 级顺序加入，且开启维度下钻 |
| 联动不生效 | 两个组件用同一数据集、且联动字段名一致 |
| 信审经办有 NULL | 过滤 `audit_man_name 不为空` |
